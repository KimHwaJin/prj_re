# 017 — DB 수명 변경의 실제 HTTP/PostgreSQL 부하 비교

상태: 80회 비교·원본 보존·독립 수치 검증 완료. 구현 브랜치 `feature/benchmark-short-db-transactions`, 부모 `4bb5c2f` (016). 애플리케이션 동작 변경 없이 측정·보고서만 추가했다. 베이스 병합·push·배포는 수행하지 않았다.

[상세 결과](../reports/db-scope-comparison-2026-09-29/README.md) 및 [전체 상세 본문](../reports/db-scope-comparison-2026-09-29/report.md)를 참고한다.

- 비교는 015/64ad96f → 016/4bb5c2f의 증분이다. 전체 리팩터링 개선율은 아니다.
- 사용자 1·10·30·50·100명 CRUD·초기 혼합·4단계 HITL, 느린 모델/작은 풀/넉넉한 풀/단일 실행 자리까지 20조건, 각 버전 2회. 2,852 시나리오, HTTP 145,563건.
- 100명 초기 혼합에서 Run당 Worker DB 연결 점유 2.131→0.110 연결초(-94.8%), 백그라운드 CRUD 서버 p95 247.1→42.8ms(-82.7%).
- 100명 전체 HITL 평균 48.41→43.35초(-10.4%). 현재 평균 약 39.20초가 큐 대기로 남았다. 모델/연결 점유를 큐 대기와 구분한다.
- 연결 4개·자리 4개·LLM 5초에서는 직전 0/20 완료·복구 필요 8개, 현재 20/20 완료·복구 필요 0개. cancel API 없이 취소 감시의 풀 timeout으로 직전 Worker가 중단됐다.
- 빠른 10명 조건은 추가 SELECT·폴링 경계로 일부 지연 증가가 관측됐다. 대조군의 역방향 결과도 보고서에 포함한다.
- 기본 조건 60회 전체 완료/소유권 반환. 독립 검증에서 핵심 수치와 조인을 재계산했으며 4,360 단계 중 3건의 36ms 미만 시각 잔여를 숨기지 않고 기록했다.
- 계측기·실행기·집계기·검증기·보고서 생성기는 scripts/benchmarks에 있고, 재현 조건은 METHOD.md에 있다. 원본/요약/변경 diff/환경 버전도 보존한다.

실제 LLM/Executor/Redis, Kubernetes, 장시간 운영은 미검증이다. 기존 서비스는 변경하지 않았으며 이번 전용 PostgreSQL 컨테이너·볼륨을 제거했다. 후속 우선순위는 짧은 DB 경계를 유지한 저장·조회 비용 분석 및 실행 자리/DB 예산 조합 검증이다. 관리자 복구 API는 기존 결정대로 별도 후속이다.

HTML은 schema/구조 검증을 통과했지만 실제 브라우저 화면 검증은 기동 timeout 및 file URL 정책 제한으로 미완료다. 동일 canonical artifact의 전체 본문·표·차트 원본을 report.md로 제공한다. 수치 검증과 화면 검증을 구분한다.
